01The system at a glance

Seven layers. A message enters at the top, work happens in the middle, results land in storage and come back as a notification. The brain sits beside every layer, because every agent reads it before acting and writes to it after.

The three design rules the whole thing rests on

The Operator never does domain work. It plans, routes, collects approvals and compiles the brief. Specialists do the work. That keeps the one component every request passes through small, testable and boring, which is exactly what you want it to be.

Every action that costs money or touches a customer passes an approval gate that fails closed. Expired, malformed or missing approval means nothing happens and the agent asks again. There is no path where silence becomes consent.

The brain is the only shared state between agents. Agents never call each other directly. Creator Outreach does not tell Ad Creative which UGC came in; it writes to the brain, and Ad Creative reads it. That is what makes agents independently deployable and independently sellable.

02The Operator: the one they actually talk to

You are right that there has to be one. Every message from the owner lands on the Operator, whichever channel it came through. It is the crew's manager, and it is the personality of the product.

GateHolds the global guardrails above every agent's own: total daily spend, total messages sent to customers per day, who is allowed to approve whatLet a per-agent guardrail override a global one. Global always wins
Collect approvalsTurns a paused agent's request into a chat message with buttons, routes the answer back, expires it at 24 hoursBatch approvals into one "approve all" button. Each is a separate decision
ReportCompiles the Monday brief from every agent's week, and answers "what happened" questions from the brain and the run logReport anything it cannot point to a run or a brain entry for

Why it is small on purpose. The Operator is the one thing that can break everything, so it carries the least logic. It has no tools of its own except the queue, the brain, the run log and the gateway. It cannot call Shopify, it cannot send a creator a DM, it cannot spend a rupee. If it is compromised or confused, the worst it can do is dispatch a job that then hits the specialist's own guardrails and the spend cap.

Why these three

Ad Growth is the largest single money lever a store has and the biggest hole in the current lineup: we make creative and then do nothing with the account it runs in. UGC Seeding is the one nobody else can easily copy, because you already have the creator discovery pipeline built and verified, and it feeds Ad Creative with real footage for free. Retention and Winback is where the lifetime value sits and it is the least served by anything a store owner can buy today.

Affiliate is a good agent for a mature brand and a distraction for a new one. Social Engagement is high-touch and the riskiest to run autonomously. Offer and Landing Page is strong but overlaps Store Fix enough that it can wait.

On your question about retention and content

Content does not cover retention. Content Publishing is acquisition-side: it makes reels and carousels that bring new people in. Retention is a different job with different data. It needs order history, segments and lifetime value, and its output is a campaign to people who already bought. Lifecycle Agent builds the always-on flows once (welcome, cart, post-purchase). Retention and Winback is the person who then uses that plumbing every week to decide who gets what. Plumbing versus operator.

Format. Markdown files in R2, one folder per customer, indexed in D1 for fast lookup of the current version of each layer. Markdown because the owner can read and edit it, because Tier 1 buyers hold it in their own hands, and because it is the format every AI runtime already reads. The Operator loads only the layers a job needs, never the whole brain, which keeps runs cheap.

12Infrastructure and the repeatable playbook

Nothing runs from a laptop. The control plane is Cloudflare because you already run a production pipeline there. The execution plane is one small VM because Workers cannot run a ten-minute agent loop with FFmpeg in it.

The repeatable playbook, once the first agent runs

  1. Define. Write the agent folder: AGENT.md with the three modes, assets, one worked example, manifest.json with tools and guardrails.
  2. Register. Add its row to D1: name, modes, tools it may call, default cost estimate, default schedule.
  3. Handle. Write its queue handler on the VM: load the brain layers it needs, run, request approvals through the gateway, write outputs to R2, write events and cost to D1.
  4. Schedule. Point a Cron Trigger at it for Hosted customers who have it switched on.
  5. Prove. Run it on five real stores. Ship the worked example. Publish the real cost number.

Ad Creative goes first because it is already built and verified, it cannot run in a chat so it proves the cloud tier is necessary, every run produces 40 images of marketing collateral, and it already has revenue attached as the $99 add-on. After it, steps 1 to 5 are the same for every agent, and each one is a week rather than a month.

Cost control, before the first Hosted customer

Per-customer monthly spend cap in D1, checked at dispatch. A run that would cross the cap queues and alerts rather than executing. Every run records its cost. A global daily cap across all customers as the last line. Without these, one runaway loop is a bad month, and with them the estimates in section 11 stop being estimates.
